\begin{abstract}
This laboratory experiment builds a complete desktop-object detection system from self-collected data to edge-device deployment. Four classes—mouse, laptop, cup, and phone—were extracted from recorded videos, manually annotated in ISAT, converted to YOLO format, and used to train a YOLOv8n detector from random initialization. No COCO or other external pretrained checkpoint was loaded. The final system displays class names, bounding boxes, confidence scores, object counts, and frame rate on a Jetson Orin, and the ROS2 node publishes the detections on \code{/detections}. The dataset contains 595 images split into 421 training, 87 validation, and 87 diagnostic-test images. The final validation results are Precision 0.658, Recall 0.748, mAP@0.5 0.766, and mAP@0.5:0.95 0.701. On 80 independent physical-object photographs, four classes were tested with 20 images each; 72 images passed, giving a 90\% image-level recognition rate. The Jetson demonstration shows approximately 15 FPS. Data, code, weights, results, video, documentation, and this LaTeX source are archived for acceptance and reproduction.
\end{abstract}

\section{Objective and Acceptance Requirements}
The purpose of this experiment is to practice the complete workflow of a practical object detector rather than only calling a pretrained model. The required workflow includes selecting at least two desktop-object classes, collecting and annotating images, training a detection model, running it on Jetson, displaying the class, bounding box and confidence in real time, and publishing the result through ROS2.

The acceptance checks are mapped to explicit evidence. The system must recognize at least two classes simultaneously; the recognition accuracy on at least 20 physical objects must be no lower than 80\%; the Jetson display must run at no less than 5 FPS; and the final submission must preserve the dataset, model, programs, result video, running instructions, and typical error cases. This report uses four classes and tests 80 independent photographs, so the physical-object test is four times larger than the minimum requirement.

\resultbox{\textbf{Acceptance result}\quad Four classes are supported; 72 of 80 independent photographs pass (90\%); the Jetson demonstration displays approximately 15 FPS; the dataset, model, programs, video, instructions, report, and error cases are archived.}

\section{Principle and Experimental Workflow}
YOLOv8 performs image preprocessing, one network forward pass, and non-maximum suppression (NMS) to produce object classes and bounding boxes. During training, the predicted boxes and class distributions are compared with manually annotated boxes and the network parameters are updated by back-propagation. During validation, an IoU matching rule connects predictions with ground truth and provides Precision, Recall, and mAP. During deployment, the camera frame enters the detector node and the same inference result is sent to the display path and the ROS2 publication path.

The experiment follows the sequence “collect—screen—annotate—convert—train—validate—independent test—deploy—accept—archive.” Original images and ISAT JSON files preserve the annotation basis, \code{dataset/yolo/} is the training input, the training directory stores parameters and curves, the independent-test directory stores per-image decisions and failures, and the video and documentation directories preserve the edge-device evidence. The workflow therefore connects an input image to a model file, a running program, a result frame, and a final report.

The first four steps determine whether the model receives reliable supervision: screening controls sample quality, ISAT supplies object boundaries, conversion produces normalized YOLO labels, and random-initialization training writes the information into model parameters. The later steps examine practical usability from different angles. The annotated validation set measures detector quality, the independent photographs test unseen appearances and placements, Jetson checks real-time operation, and ROS2 checks whether another node can consume the result.

\section{Data Collection, Annotation, and Split}
The dataset contains 595 images extracted from desktop-object videos. The four classes are \code{mouse}, \code{laptop}, \code{cup}, and \code{phone}; they cover small targets, thin outlines, reflective surfaces, and device appearance variation. Each visible target was manually boxed in ISAT. The ISAT JSON polygons were converted into YOLO detection labels in the form \code{class\_id x\_center y\_center width height}, with all coordinates normalized to $[0,1]$.

The split was made by identifying the source video and assigning contiguous time blocks within each source, rather than randomly scattering adjacent frames. This reduces the chance that nearly identical poses appear in both training and validation. The 80 independent photographs are kept outside the 595-image dataset and contain 20 photographs per class, with different physical objects, orientations, distances, and backgrounds. They therefore provide a separate image-level check of practical recognition.

Annotation quality was checked at three levels. First, each box was inspected to ensure that it covered the visible object without an obvious boundary error. Second, class IDs and image names were checked against \code{data.yaml}. Third, the converted labels were checked for normalized coordinates, valid class ranges, empty-label anomalies, and image-label correspondence. These checks are particularly useful for reflective phones, thin laptop edges, and small mice, where a slight boundary error can change the training signal.

\section{Training Configuration}
The model was trained from \code{yolov8n.yaml} with random initialization. The training process did not load \code{yolov8n.pt}, COCO weights, or another external checkpoint. This choice makes the relation between the self-built dataset and the final four-class weights explicit. The training command was:

\begin{quote}\small\code{python train\_yolo.py --epochs 100 --batch 16 --device 0 --workers 0}\end{quote}

Training used 100 epochs, 640-pixel input images, batch size 16, GPU device 0, zero data-loader workers, seed 42, automatic optimizer selection, standard YOLO augmentation, and early-stopping patience of 25. Only the training and validation splits were used for parameter optimization. The diagnostic test split was retained until training finished, so it was not used to choose the checkpoint.

The training directory preserves the argument file, loss and metric curves, confusion matrices, and the final weight. The curves are used to inspect convergence and late-stage stability, while the confusion matrix shows whether a class is systematically confused with another class. Keeping both forms of evidence is more informative than reporting only one final scalar.

\section{Validation and Independent Physical-Object Results}
The final four-class model produced the following validation results on \code{dataset/yolo/}: Precision 0.658, Recall 0.748, mAP@0.5 0.766, and mAP@0.5:0.95 0.701. At the class level, mAP@0.5:0.95 was 0.723 for mouse, 0.877 for laptop, 0.428 for cup, and 0.776 for phone. The lower cup value is consistent with its reflective rim, handle, and similarity to the desktop background.

\section{Jetson Deployment and ROS2 Publication}
The final four-class weight was copied to Jetson Orin and loaded by \code{realtime\_detect.py}. The program reads a USB camera, performs GPU inference, draws bounding boxes, class names and confidence scores, counts objects by class, computes a sliding-average FPS, and can save an annotated MP4. The camera and output video use 640$\times$480, while inference uses 320 pixels to keep the complete read—infer—NMS—draw—display chain responsive.

The Jetson demonstration video displays approximately 15 FPS, which is above the 5 FPS acceptance threshold. The confidence threshold was set to 0.35 for the demonstration so that very low-confidence boxes were less distracting. This display threshold changes the visual filtering only; it does not alter the trained weights or the offline validation metrics.

\begin{figure}[H]
\centering
\includegraphics[width=0.98\columnwidth]{jetson_demo_montage.jpg}
\tightcaption{Frames from the Jetson demonstration video, showing boxes, classes, confidence, object counts, and FPS}
\end{figure}

The ROS2 node \code{ros2\_detector\_node.py} subscribes to \code{/camera/image\_raw} as \code{sensor\_msgs/Image}, converts frames with \code{cv\_bridge}, runs the detector, and publishes \code{vision\_msgs/Detection2DArray} on \code{/detections}. Each detection contains the class name, confidence, and pixel-coordinate bounding-box information. The documented verification command is \code{ros2 topic echo /detections --once}; the source and startup instructions are included in the submission package so the interface can be checked when the Jetson environment is available.

\section{Typical Error Cases and Discussion}
Eight of the 80 independent photographs fail: three cups, one laptop, two mice, and two phones. The cup failures are mainly related to low contrast between the object edge and the desktop, reflective surfaces, and handle or rim appearance. The laptop failure is associated with an oblique view and screen reflection. The mouse failures involve small apparent size or partial occlusion. The phone failures involve new-device appearance, low contrast, and changes in placement direction.

\begin{figure}[H]
\centering
\includegraphics[width=0.92\columnwidth]{../results/independent_test_80/errors/04_cup_example.jpg}
\tightcaption{Independent-test failure example: the true class is cup, but a background laptop is predicted as the target (04\_cup.jpg)}
\end{figure}

The example illustrates why image-level failure analysis matters. The detector did produce a high-confidence box, but the box covered a background laptop rather than the cup. We therefore record errors along three dimensions: class, pose, and background. This makes the next data-collection step concrete: add difficult cup viewpoints and reflective backgrounds, add occluded or small mouse examples, and add phone orientations and newer device appearances. The current errors do not indicate that every class needs the same amount of additional data.

\section{Submission Materials and Reproduction}
The material package is organized as “input—model—program—result—documentation—report.” The dataset contains the YOLO images and labels plus the 80 independent photographs. The model directory contains the final four-class \code{best.pt}. The program directory contains training, evaluation, real-time detection, ROS2, and Jetson deployment scripts. The result directories contain training curves, confusion matrices, per-image independent-test records, failures, and the Jetson videos. The report directory contains this PDF and its LaTeX source.

The main reproduction steps are:
\begin{enumerate}
\item Install the Windows training dependencies from \code{requirements.txt} and verify the YOLO dataset configuration.
\item Run \code{convert\_isat\_to\_yolo.py} when the ISAT annotations need to be regenerated, then run the training command in Section IV.
\item Run \code{evaluate\_yolo.py --device 0} for the annotated validation and diagnostic outputs.
\item Copy \code{models/best.pt} to Jetson, start \code{realtime\_detect.py}, and check the overlay and displayed FPS.
\item Start \code{ros2\_detector\_node.py} and use \code{ros2 topic echo /detections --once} to inspect the published message.
\end{enumerate}

The report, dataset, model, code, video, instructions, and error cases are stored in the public repository \url{https://github.com/9161942-boop/robotics-experiment-1}. A SHA-256 manifest is included in the complete package. The report records the final four-class model and the independent-test statistics; older exploratory results are not used as acceptance evidence.

\section*{Summary and Reflections}
This experiment completed a traceable path from self-collected images to an edge-device detection system. The main summary and reflections are:
\begin{itemize}
\item \textbf{Data and training:} The 595-image dataset was manually annotated and divided into 421 training, 87 validation, and 87 diagnostic-test images. Starting from \code{yolov8n.yaml} rather than an external checkpoint made the training source explicit and kept the final four-class weight connected to the self-built dataset.
\item \textbf{Recognition quality:} The validation metrics quantify the quality of predicted boxes, while the 80 independent photographs evaluate practical recognition. The 72/80 result (90\%) shows that the system meets the course threshold on unseen physical objects, and the class-wise table reveals where further sampling would be most useful.
\item \textbf{Deployment and interface:} The Jetson video demonstrates the complete camera-to-display chain at approximately 15 FPS. The ROS2 node packages the same detections as \code{Detection2DArray} on \code{/detections}, so the result can be consumed by later tracking, counting, or manipulation modules.
\item \textbf{Lessons and improvements:} The remaining failures are concentrated in reflective cups, small or occluded mice, and phones with changed appearance or orientation. Future work should add these difficult conditions and evaluate TensorRT optimization on Jetson, while keeping the independent test set fixed for comparison.
\end{itemize}

The practical value of this experiment is the complete engineering chain: data are traceable to labels, labels are traceable to weights, weights are traceable to a running program, and the program is traceable to saved videos and ROS2 messages. This organization makes the system easier to demonstrate, reproduce, and improve than a detector accompanied only by a single accuracy number.
